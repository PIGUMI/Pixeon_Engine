ImageRender 透過問題の診断レポート
作成日: 2025年12月4日

==================================================
■ 問題の概要
==================================================
ImageRenderコンポーネントで描画される画像が透過（アルファブレンディング）されない問題。


==================================================
■ 根本原因
==================================================
ImageRender::Draw() 関数において、DepthStencilState（深度ステンシルステート）が
設定されていないことが問題の主要因です。

具体的には：
1. ImageRender.cpp の 535行目で OMSetBlendState() によりブレンドステートは正しく設定されています
2. しかし、OMSetDepthStencilState() の呼び出しが存在しません
3. このため、以前のレンダリング処理で設定された深度ステンシルステートがそのまま使用されます


==================================================
■ 技術的な詳細
==================================================

【現在の実装状況】

1. ブレンドステート設定 (ImageRender.cpp 105-119行目)
   ✓ 正しく実装されています
   - BlendEnable = TRUE
   - SrcBlend = D3D11_BLEND_SRC_ALPHA
   - DestBlend = D3D11_BLEND_INV_SRC_ALPHA
   - BlendOp = D3D11_BLEND_OP_ADD
   
   これにより、標準的なアルファブレンディングの計算式が適用されます：
   最終色 = (ソース色 × ソースアルファ) + (デスティネーション色 × (1 - ソースアルファ))

2. シェーダー実装 (PS_ImgQuad.hlsl 11-15行目)
   ✓ 正しく実装されています
   - テクスチャのRGBA値を取得
   - Color値を乗算して出力
   - アルファチャンネルも正しく出力されます

3. 深度ステンシルステート設定
   ✗ 実装されていません
   - ImageRender.h に深度ステンシルステートの静的メンバー変数が存在しない
   - ImageRender.cpp に深度ステンシルステートの作成・設定処理が存在しない


==================================================
■ 問題が発生するメカニズム
==================================================

Direct3D 11のレンダリングパイプラインでは、深度ステンシルステートを明示的に
設定しない場合、以前に設定されたステートがそのまま使用されます。

シナリオ1: 深度テストが有効な場合
- 前の3Dオブジェクトのレンダリングで深度テストが有効化されている
- ImageRenderで画像を描画する際、深度テストが実行される
- 画像の位置が深度バッファの既存値より奥にある場合、描画がスキップされる
- または、画像が深度バッファに書き込まれ、後続の透過オブジェクトが描画されない

シナリオ2: 深度書き込みが有効な場合
- ImageRenderで画像を描画する際、深度値が書き込まれる
- 画像の背後にある他の透過オブジェクトが深度テストで失敗する
- 結果として、正しい描画順序で透過が実現できない

シナリオ3: レンダリング順序の問題
- 透過オブジェクトは通常、後ろから前に描画する必要がある
- 深度テストと深度書き込みが有効だと、描画順序に関係なく
  深度値により描画が制御されてしまう


==================================================
■ 解決策
==================================================

以下の実装が必要です：

1. 深度ステンシルステートの作成
   - 深度テストを無効化（DepthEnable = FALSE）または
   - 深度テストは有効だが深度書き込みを無効化（DepthWriteMask = D3D11_DEPTH_WRITE_MASK_ZERO）
   - ステンシルテストは無効化（StencilEnable = FALSE）

2. ImageRender.h への追加
   - 静的メンバー変数の追加：
     static Microsoft::WRL::ComPtr<ID3D11DepthStencilState> s_depthStencilState;

3. ImageRender.cpp への追加
   - EnsureDepthStencilState() メソッドの実装
   - ImageRender::Draw() 内で OMSetDepthStencilState() の呼び出し

推奨される深度ステンシルステート設定：

オプションA（深度テスト無効）:
  D3D11_DEPTH_STENCIL_DESC desc = {};
  desc.DepthEnable = FALSE;
  desc.DepthWriteMask = D3D11_DEPTH_WRITE_MASK_ZERO;
  desc.StencilEnable = FALSE;

オプションB（深度読み取りのみ）:
  D3D11_DEPTH_STENCIL_DESC desc = {};
  desc.DepthEnable = TRUE;
  desc.DepthWriteMask = D3D11_DEPTH_WRITE_MASK_ZERO;
  desc.DepthFunc = D3D11_COMPARISON_LESS_EQUAL;
  desc.StencilEnable = FALSE;

オプションAは2D UIや画面オーバーレイに適しています。
オプションBは3D空間での透過オブジェクトに適しており、正しい遮蔽関係を
保ちながら透過を実現できます。

   - OMSetBlendState() の直後に OMSetDepthStencilState() を呼び出し


==================================================
■ 検証方法
==================================================

修正後、以下の点を確認してください：

1. 透過画像が正しくアルファブレンディングされること
2. 2Dモード、ビルボードモード、3Dモード、UIモードすべてで透過が機能すること

4. 透過画像の背後にある3Dオブジェクトが見えること

■ 補足事項
==================================================

この問題は、Direct3D 11のステートマシンの特性に起因しています。
一度設定されたレンダリングステートは、明示的に変更するまで保持されるため、
各レンダリングコンポーネントは必要なステートを全て設定する責任があります。

ImageRenderコンポーネントは、ブレンドステートは正しく管理していましたが、
深度ステンシルステートの管理が欠けていたため、透過が正しく機能しない
状況が発生していました。

同様の問題を防ぐため、新しいレンダリングコンポーネントを実装する際は、
以下のステートを全て明示的に設定することを推奨します：
- ブレンドステート（OMSetBlendState）
- 深度ステンシルステート（OMSetDepthStencilState）
- ラスタライザーステート（RSSetState）
- サンプラーステート（PSSetSamplers）


==================================================
■ 結論
==================================================

ImageRenderで画像が透過しない根本原因は、深度ステンシルステートが
設定されていないことです。ブレンドステートとシェーダーの実装は
正しいため、深度ステンシルステートの作成と設定を追加することで
問題は解決されます。

修正の影響範囲は限定的であり、既存のコードを壊すリスクは低いです。
上記の解決策を実装することで、ImageRenderコンポーネントは
すべてのプレースメントモードで正しく透過処理を行えるようになります。
